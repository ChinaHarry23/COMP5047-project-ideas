# 共用架构约定（20 个构想同一套）

> **English**：[[architecture_shared_en]]
> **先读这一页。** 下面每个构想复用同一块 MCU、同一套固件分层、同一份默认引脚、同一种失效语法、同一张周历。各构想的 pack 只写 **不一样的部分**：传感器、执行器、外壳、状态机、演示。

Pass 产品始终是：**一块单片机 + ≥2 类传感器 + ≥1 路非屏幕驱动 + 自制外壳**。Apple Vision Pro 是 **第二展位**。头显注视不得触发电机、泵、闩、阀。

---

## 1. 为什么要共用栈

五名计算机硕士，只剩第 7–13 周。开题本应第 4 周交，换题需导师批准。不能同时学新 MCU、新 CAD、新云端：

| 决定 | 选择 | 理由 |
|---|---|---|
| MCU | **ESP32-S3** DevKitC-1（N8R8 或 N16R8），USB-C，排针已焊 | I2C、UART、ADC1、LEDC PWM、WiFi，可选摄像头/I2S。第 3–8 周实验已用 ESP32 |
| 固件 | **ESP-IDF + FreeRTOS，C** | 与旧护柱包一致。提交树里不要 Arduino，proposal 和仓库才能对上 |
| 执行 | **MG90S**（180° 金属齿）和/或 **5 V 泵 + 逻辑电平 N-MOSFET** | 第 7 周电机。SG90 遇风不够力 |
| 夜/黄昏 | **BH1750**（或 VEML7700）走 I2C | 第 4 周智能灯同一谱系 |
| 存在 | **LD2410C** 毫米波走 UART | 可设距离门；演示 1–5 m 优于 PIR |
| 气候 | **DHT22** 和/或 **DS18B20** | 热、水、孵丘、蜂巢、土壤模型 |
| Credit API | **气象局 / Open-Meteo**、**图像分类** 或 **BirdNET 一类** 声音 | 第 8 周。不要把 ChatGPT 当产品 |
| 外壳 | **Fusion 360 → FDM PETG**（木/岩语境就用木材） | 第 5/9 周。形态 **就是** 生态 |
| 电源 | 第 13 周 **USB-C 台供**；18650 + 降压写进 v2 | 不要把太阳能当演示 |
| 网络 | WiFi STA 拉 API；**BLE 只给维护日志** | 栖息地不需要手机界面 |

云端 / 手机 **不在** 运行时栈里。ALA / iNaturalist / DCCEEW 是 **证据**，不是在线查询。

## 2. 一句架构（每个构想都是这个形状）

```
世界（点名的生态）
   → 感知（≥2 类：模拟、I2C、UART 或 I2S）
   → 融合（ESP32-S3 / ESP-IDF，保持 + 滞后）
   → 状态机（策略只住在一个任务里）
   → 驱动（舵机 / 泵 / MOSFET / 旗 — 无屏幕）
   → 电源（USB 台供；18650 为 stretch）
演示 = 校园模型 + 回放 / 玩偶 / 水壶。绝不用活体名录种。
```

信任边界：栖息地里的东西 **不必** 联网。Credit API 挂了，状态机必须有写明的 **失效开放 / 关闭 / 关断**，把正义写进转移，而不是转圈。

## 3. 默认引脚约定（ESP32-S3 DevKitC-1）

具体丝印因板而异。这是 **组内合同**。只有构想 pack 里写明、且摄像头/I2S 板冲突时才改。

**第 6 周实验硬规则：** WiFi 会废掉 **ADC2**。所有模拟量（浊度、土壤、包络、电池）走 **ADC1**。

| 功能 | 总线 | 默认 GPIO | 说明 |
|---|---|---|---|
| I2C SDA / SCL（BH1750、MLX90614、VEML7700，可选调试屏） | I2C0 | **8 / 9** | 3.3 V；模块没上拉就加 4.7 kΩ |
| LD2410 UART TX/RX（模块 TX → MCU RX） | UART1 | **17 / 18** | 常见 256000 baud。有的是 5 V 逻辑 → **电平转换** |
| 1-wire（DHT22 数据，或 DS18B20 DQ） | GPIO | **4** | DS18B20 需 4.7 kΩ 上拉到 3.3 V |
| 第二路气候 | GPIO | **10** | 第二只 DS18B20 也可挂同一 1-wire |
| 模拟 1（浊度 / 土壤 / 包络 / TDS） | ADC1 | **1**（ADC1_CH0） | 只收 0–3.3 V |
| 模拟 2（电池 / 第二路光学） | ADC1 | **2** | 可选 |
| 主执行 MOSFET / 泵 / LED | LEDC | **6** | 逻辑电平 N 管（AO3400 / IRLML2502 一类） |
| 主舵机（MG90S） | LEDC 50 Hz | **7** | 舵机吃 5 V，**共地** |
| 第二舵机（通风、旗、盖、瓣） | LEDC 50 Hz | **11** | |
| 维护用琥珀灯 | LEDC / GPIO | **5** | 底面 / 只给人看。不得照亮栖息地 |
| 限位 / 浮子 / 洗靴完成 | GPIO 入 | **12** | INPUT_PULLUP |
| 备用 / 摄像头 PWDN / I2S WS | — | **13+** | 见各构想 pack |
| USB | USB-C | — | 必须是 **数据线**，不能只充电 |

3.3 V 与 GND 共用。MCU 旁 **100 nF + 10 µF**。舵机和泵走 **5 V**，绝不从 ESP32 的 3.3 V 脚取电。

**舵机转动时不要采 ADC**（电机伪迹）。`task_actuate` 置 `ctx.motor_busy`；感知任务丢掉这一窗。

## 4. 功耗量级（USB 台供）

| 状态 | 电流 | 含义 |
|---|---|---|
| 空闲感知（I2C + UART + ADC，执行器停好） | 数十 mA | 默认是关 / 闭 / 松 — 感知仍在跑 |
| MG90S 保持 | ~10–20 mA | 能机械停就机械停，不要 PWM 较劲 |
| MG90S 转动 | 200–500 mA 尖峰，<1 s | 劣质 USB 会掉电；用 2 A 电源 |
| 5 V 微型泵 | 100–400 mA | MOSFET + 续流二极管 |
| ESP32-S3-CAM + WiFi 发射 | 200–400 mA 突发 | 用摄像头就把 5 V 按这个算 |
| USB 台供 | 第 13 周够用 | 18650 + 降压写成 v2，不当演示 |

## 5. 固件分层（ESP-IDF）

```
┌─────────────────────────────────────────────────────────────┐
│  演示通路跑通之后才做的可选层                                │
│  TinyML · ESP-DSP FFT · BLE 日志 · visionOS 伴侣            │
├─────────────────────────────────────────────────────────────┤
│  应用：状态机 + 执行策略                                     │
│  （具名状态只住这里 — 各构想 pack 列出）                      │
├─────────────────────────────────────────────────────────────┤
│  情境融合                                                    │
│  保持 · 滞后 · 距离门 · NVS 缓存 · 故障                      │
├─────────────────────────────────────────────────────────────┤
│  驱动                                                        │
│  i2c · uart · adc · 1-wire · ledc PWM · gpio · wifi sta     │
├─────────────────────────────────────────────────────────────┤
│  ESP-IDF · FreeRTOS · ESP32-S3                              │
└─────────────────────────────────────────────────────────────┘
```

**策略只住在 `task_fsm`。** 驱动不得自己淡灯、开泵、再开一个超时「帮忙」。

### 共用 FreeRTOS 任务

| 任务 | 周期（典型） | 读 | 写 |
|---|---|---|---|
| `task_sense_*` | 20–1000 ms | 总线 | `ctx` 字段 |
| `task_api` | 1–10 min | WiFi / HTTP | `ctx.forecast_*`、`ctx.class_id`、`ctx.api_ok` |
| `task_clock` | 1 s | NVS 日落 + 运行时间 | `ctx.is_night`、`ctx.civil_twilight` |
| `task_fsm` | 50 ms | `ctx` | `cmd.*` |
| `task_actuate` | 20 ms | `cmd` | LEDC / GPIO；置 `ctx.motor_busy` |
| `task_maint` | 1 s | 故障、空罐、堵转 | `cmd.amber` |

### 共用 `ctx` 字段（各构想再加自己的）

```
api_ok            false → 走该构想的 fail-* 规则
fault             传感器超时、掉电、空罐、堵转
motor_busy        舵机/泵在动；ADC 丢弃窗
is_night          缓存的气象局日落–日出
civil_twilight    照度带和/或太阳高度缓存
maintainer        琥珀脉冲；不是野生动物主张
```

NVS：缓存日落、上次好预报、标定。无线电没了，**不要**编预报。

### 建议仓库布局（每构想一份，或一个仓库用 `Kconfig` 选构想）

```
firmware/
  main/
    app_main.c
    ctx.h
    fsm.c / fsm.h          ← 唯一写正义的文件
    drivers/lux.c mmwave.c climate.c analog.c pump.c servo.c wifi_api.c
    nvs_cache.c
  CMakeLists.txt

cad/                       ← Fusion + STEP + 3MF
docs/                      ← ESD 表、证据、视频脚本
visionos/                  ← 第 9 周之后才开工
```

## 6. 失效语法（写进报告）

每个执行器只选 **一种**，口号不要和代码打架：

| 语法 | 含义 | 何时用 |
|---|---|---|
| **失效关断 Fail-off** | 泵 / 喷雾 / 灯保持 **关** | 热浪庇护、滴灌、水文周期 — 误开就是伤害 |
| **失效开放 Fail-open** | 缝 / 跑道对受益者保持 **开** | 分类器挂了时给负鼠、袋狸、企鹅体型 |
| **失效关闭 Fail-closed** | 缝对威胁保持 **关** | 猫体型；企鹅门的狗一侧；饵盖 |
| **失效落下 Fail-down** | 遮帘 / 绳 / 荫到 **保护姿态** | 玻璃撞鸟、果网松弛、洗靴闸 |
| **失效停泊 Fail-park** | 叶片 / 石头 / 绳停止运动 | 风、雨、动物已经在物件上 |

「正义写在状态机里」的意思是：fail-* 是一条 **转移**，不是一句配图说明。

## 8. 共用采购（先下一单，再加各构想差额）

演示关键模块 **买两份**。从澳大利亚：淘宝 / 菜鸟或转运；10–21 天。USB-C 必须是 **数据线**。

**必买：** 2× ESP32-S3 DevKitC-1；BH1750；LD2410C；2× MG90S 180° 金属齿；逻辑电平 N-MOSFET + 续流二极管；琥珀 LED；杜邦线 + 面包板；PETG；5 V 2 A USB 电源。

**常买：** DHT22；防水 DS18B20 ×2；18650 + 5 V/3.3 V 降压；电平转换；限位开关。

**各构想差额** 写在对应 pack（泵、摄像头、I2S 麦、浊度 LED+光电管、土壤湿度、ToF、风速、水缸）。

**第 13 周不要：** 把 192 kHz I2S FFT 当唯一检测；手机 App 当界面；太阳能当唯一电源；活体名录种；超声波「驱虫」喇叭；ChatGPT 当 Credit API。

## 9. 各构想 pack 怎么读

骨架相同：

1. **挑战 + 非人类利益相关者** — 状态机为谁服务。
2. **一句架构 + 图 + 数据流表。**
3. **硬件** — 分层、引脚改动、外壳、电源、BOM 差额。
4. **软件** — 任务、额外 `ctx`、完整状态机、滞后、fail-*。
5. **实施计划** — 按周验收、五人活、第 13 周演示脚本。
6. **Vision Pro** — 探询叠加；不能开火执行器。
7. **风险 / 诚实** — 校园模型，不声称种群恢复。

报告里的 ESD（期望–感知–期望状态）写给 **非人类**。若干构想要写 **两张** ESD 表（互相冲突的 Desired）。
